# spec：赚了要不要走？——止盈交易规则

> 在当前项目中执行命令，使用本 spec 指定的环境。遵守 TRAE 当前的权限设置；需要额外权限时，先说明原因和访问范围，取得用户确认后再继续，不要求关闭沙箱或启用“完全访问”。

## 上下文

在 `q4-when-to-trade.ipynb` 中已有：
- 不同再平衡间隔的对比结果
- 采用不同止损阈值的配置及其对比结果
- 沿用 spec 01 的 `FEE_MODEL` 和 `run_backtest(frequency, fee_model=None, order_rules=None)` 辅助函数

当前需要检查达到一定盈利幅度后主动卖出的止盈交易规则会怎样影响结果。

## 任务目标

给策略加上止盈交易规则，比较不同止盈阈值的效果。

## 执行要求

沿用 spec 01 的固定数据窗口：`START = "2021-01-01"`，`END = "2026-03-18"`。不得重新引入 `today` 或 `now`。

1. 阅读下列 open-xquant 源码，了解所列类、函数或方法的输入、输出和参数含义：
   - `oxq.rules.TakeProfitRule`（本实验将交易规则通过 `Engine.run(rules=[...])` 传入）

2. 解释 `TakeProfitRule` 的工作原理：
   - 当持有仓位时，`TakeProfitRule` 每个交易日以 `avg_cost × (1 + threshold)` 计算止盈线，并用对应投资对象的当日收盘价检查是否达到止盈阈值
   - 达到止盈阈值后，规则返回该投资对象的清仓目标。`Engine` 将目标转换成 `market` `SELL` 订单，`SimBroker` 按该投资对象的当日收盘价成交。锁定版本并不预先提交 `limit` 挂单
   - 明确同一收盘价用于判断和成交、且未模拟滑点，是本章的教学简化，不代表真实交易可以在看到收盘价后仍以同一价格成交

3. 从 spec 02 的 3 个止损阈值中，**用代码动态选出**当前样本中简化夏普最高的配置所采用的止损阈值，与 spec 02 确定的再平衡间隔 `BEST_FREQ` 一起作为后续基础配置（不要硬编码数字；也不能据此认定这套配置在另一段未参与选择的数据上仍然最优）：
   ```python
   BEST_SL = max([sl for sl in STOP_THRESHOLDS if sl is not None],
                 key=lambda sl: results_sl[sl].sharpe_ratio())
   ```

4. 定义 4 组对比：不止盈配置，以及止盈阈值分别为 10%、20% 和 30% 的配置（`threshold=0.10`、`0.20`、`0.30`）。

5. 全部回测均计入交易成本。调用 spec 01 定义的 `run_backtest` 辅助函数。每组都保留止损交易规则，只有 `TP` 不为 `None` 时才创建止盈交易规则：
   ```python
   order_rules = [StopLossRule(threshold=BEST_SL)]
   if TP is not None:
       order_rules.append(TakeProfitRule(threshold=TP))
   run_backtest(
       frequency=BEST_FREQ,
       fee_model=FEE_MODEL,
       order_rules=order_rules,
   )
   ```
   在 `run_backtest` 内部，所有规则与 `RebalanceFrequencyRule` 一起传入 `Engine.run(rules=[...])`。

6. 打印对比表：止盈阈值、累计收益率、年化波动率、最大回撤、简化夏普、成交笔数、总手续费。手续费显示保留 2 位小数，计算和差值比较使用未舍入值

7. 画净值曲线对比图（`figsize=(12, 6)`，画布大小为 12 英寸×6 英寸）：
   - 不止盈配置的净值曲线使用灰色虚线。止盈阈值为 10%、20% 和 30% 的配置分别使用紫色实线、橙色点划线和青绿色点线。
   - 归一化到起点=100。横轴标“年份”，纵轴标“归一化净值（起点=100）”
   - 标题“止盈阈值对比（计入交易成本）”

8. 打印交易记录（取止盈阈值最小的那组，展示前 10 笔），把订单的 `order_type` 字段一起打出来——让学员看到回测里订单类型这一层的存在。数量和成交价的列头分别写为“数量/份”“成交价/元”。锁定版本中，再平衡产生的订单，以及止损交易规则和止盈交易规则触发的退出单都会生成 `market` 订单，因此不能用 `order_type` 判断是哪条规则触发了卖出。如需追查触发原因，应检查运行快照中的 `rule_reasons`。

9. 打印分析（根据实际数据描述结果方向，不要预设结果方向）：
   - 采用各止盈阈值的配置相对不止盈配置的累计收益率和简化夏普变化——逐个阈值看，分别是抬高、压低，还是基本不变？
   - 不同止盈阈值之间的差异——是单调变化（越紧越差或越松越好），还是非单调（中间某个止盈阈值反向）？
   - 采用止盈交易规则的配置带来的成交笔数和手续费变化。不要把成交增量直接等同于规则触发次数
   - 与上一节中不同止损阈值的比较结果对照——2 类交易规则在你这段数据上分别压低或抬高了哪些指标，方向是否一致
   - “交易圈有句老话：‘让利润奔跑，截断亏损’。这是经验总结，不是定理——它在你这段数据上成不成立，看实验数据怎么说。”
   - “加规则之前，先问自己：这条规则的逻辑站得住脚吗？换个阈值、换段数据，结论还一样吗？”

10. 固定窗口参考结果（`START = "2021-01-01"`，`END = "2026-03-18"`，基础配置为每 10 个交易日再平衡，并采用阈值为 5% 的止损交易规则），用于判断是否复现书稿：
    - 不止盈配置：`100.79% / 10.71% / -13.25% / 1.36 / 389 / 3902.88`
    - 止盈阈值为 10% 的配置：`72.73% / 9.70% / -9.47% / 1.18 / 431 / 6702.83`
    - 止盈阈值为 20% 的配置：`83.48% / 10.04% / -13.25% / 1.26 / 409 / 5215.16`
    - 止盈阈值为 30% 的配置：`104.32% / 10.23% / -13.25% / 1.45 / 396 / 4306.30`
    - 这组数据里，止盈阈值为 10% 和 20% 的配置降低累计收益率，止盈阈值为 30% 的配置提高累计收益率和简化夏普。分析不要写成“3 种止盈阈值都降低收益”
